# Codex Project Rules

## Response Language
- Always respond in Traditional Chinese.

## Git Rules
- Git commit messages must always be written in English.
- Use concise conventional commit style when possible.
- max 72 chars
- follow conventional commits
- Example:
  - feat: add destination search
  - fix: resolve mobile layout overflow

## Code Style
- All code comments must be written in English.
- Do not use emoji or icons in code, comments, commit messages, or responses.
- Keep code minimal and production-oriented.
- Avoid overengineering.
- Never add unnecessary abstraction.
- Never introduce a framework without explicit approval.

## Refactoring Rules
- Prefer incremental safe refactoring.
- Do not rewrite unrelated files.
- Preserve existing functionality unless explicitly requested.

## Frontend Rules
- Prioritize readability and maintainability.
- Avoid unnecessary dependencies.
- Optimize for static site performance and SEO.

## Output Rules
- Before modifying files:
  - explain the plan briefly
- After modifying files:
  - summarize changed files
  - explain risks
  - provide verification steps
